    A closer look

    Coordinating services and handling partial failures+

    I design orchestration that brings together responses from multiple services behind a consistent API. Concurrent requests avoid waiting for each dependency in sequence, while shared response contracts make successful, unavailable and failed results explicit to the calling application.

    Timeouts bound how long a request can wait. Circuit breakers limit repeated calls to failing dependencies, and partial results preserve useful information when some responses are unavailable. These decisions make failure behaviour part of the application design rather than an afterthought.

    • API design
    • Concurrency
    • Resilience4j
    • Fault tolerance
    Identity, permissions and application access+

    My work combines central identity integration with application-level authorisation. Token-based authentication establishes identity; role and ownership checks determine which actions and records a user can access.

    The engineering spans Keycloak integration, JWT validation and permission-aware APIs. I consider both the identity provider and the application’s own access rules, so organisational responsibilities are reflected in the software.

    • Keycloak
    • OAuth2
    • JWT
    • RBAC
    • Authorisation
    Messaging, persistence and repeated requests+

    I use asynchronous events to separate audit-recording and notification work from the code that handles the original request. This allows those responsibilities to evolve independently while keeping the information exchanged between them explicit.

    Relational persistence retains request results and workflow state. Request identifiers allow completed results to be reused when requests are repeated, while selective caching limits unnecessary reads. My work combines RabbitMQ, PostgreSQL, Redis and schema migration tooling.

    • RabbitMQ
    • PostgreSQL
    • Redis
    • Request replay
    • Data modelling
    • Flyway
    Modernisation across the backend and interface+

    I work across Node.js/NestJS and Java/Spring Boot implementations, translating application responsibilities, data models and API contracts into the target architecture. The work involves persistence, identity and messaging decisions as well as the application code.

    On the frontend, I develop React/Next.js interfaces and request-handling components for interrupted connectivity. Local request storage and replay logic bring client behaviour into the wider system design.

    • NestJS
